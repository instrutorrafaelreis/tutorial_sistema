⚙️ PASSO 0: Criando o Ambiente Virtual (venv) e Instalando as Bibliotecas Preparação

Antes de criar o código do sistema, abra o terminal do VS Code (Ctrl + '), crie a pasta obrigatória sistema, crie o ambiente virtual e instale as bibliotecas necessárias:

# 1. Cria a pasta obrigatória chamada "sistema" e entra nela
mkdir sistema
cd sistema

# 2. Cria o ambiente virtual isolado chamado "venv"
python -m venv venv

# 3. Ativa o ambiente virtual no Windows
.\venv\Scripts\activate

# 4. Instala as 3 bibliotecas necessárias para o FastAPI com Formulários HTML
pip install fastapi uvicorn python-multipart
💡 Dica caso o PowerShell bloqueie o comando .\venv\Scripts\activate:
Se aparecer um erro vermelho de permissão (ExecutionPolicy), execute este comando antes e depois ative novamente:
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

🔍 Para que serve cada comando e biblioteca instalada?

  • python -m venv venv: Cria um ambiente virtual Python isolado dentro da pasta venv. Assim as bibliotecas instaladas não entram em conflito com o restante do computador.
  • .\venv\Scripts\activate: Ativa o ambiente virtual (você verá (venv) verde no início da linha do terminal).
  • fastapi: Framework Python usado para criar as rotas web (@app.get e @app.post).
  • uvicorn: Servidor web que executa a aplicação FastAPI localmente na porta 8000.
  • python-multipart: Obrigatório! O FastAPI precisa dessa biblioteca para ler dados enviados por formulários HTML (<form method="post"> usando Form()). Sem ela, o envio de formulário falha!
  • sqlite3 e hashlib: Não precisam ser instaladas com pip porque já vêm nativas dentro do próprio Python!

ANEXO 1 - DOCUMENTAÇÃO DE SOFTWARE (OFICINA MECÂNICA)
====================================================================

1.1 REQUISITOS FUNCIONAIS DO SISTEMA (Mínimo de 4 requisitos)

- RF01 (Autenticação e Sessão): O sistema deve permitir o login de usuários validando as credenciais no banco de dados, exibindo mensagem de erro em caso de falha e criando uma sessão autenticada com tempo de expiração.
- RF02 (Funcionalidade Principal): O sistema deve exibir na tela principal o nome do usuário autenticado na sessão, disponibilizar links de acesso aos módulos "Cliente", "Veículo" e "Agendamento", e oferecer a opção de sair do sistema (logout).
- RF03 (Gerenciamento de Clientes e LGPD): O sistema deve permitir cadastrar, listar, buscar por termo, editar e excluir clientes, garantindo que dados sensíveis (CPF e senha) sejam armazenados criptografados no banco de dados conforme a LGPD.
- RF04 (Gerenciamento de Veículos): O sistema deve permitir o cadastro e a listagem de veículos, vinculando obrigatoriamente cada novo veículo a um cliente existente no banco de dados.
- RF05 (Gerenciamento de Agendamentos): O sistema deve permitir cadastrar agendamentos de revisão, atualizar a data de um agendamento existente e listar todos os agendamentos ordenados por data, exibindo os dados completos do veículo e do seu respectivo cliente.

1.2 LISTA DE REQUISITOS DE INFRAESTRUTURA

- Linguagem de Programação: Python 3
- Framework Web / Backend: FastAPI (executado via servidor ASGI Uvicorn)
- Front-end: HTML5 (renderizado pelo próprio FastAPI)
- Sistema Gerenciador de Banco de Dados (SGBD): MySQL / SQLite3
- Sistema Operacional: Windows 10 (ou equivalente)
- Editor de Código / IDE: Visual Studio Code (VS Code)

CREATE DATABASE IF NOT EXISTS oficina_db;
USE oficina_db;

-- 1. Tabela CLIENTE (CPF e Senha em SHA-256 conforme LGPD)
CREATE TABLE IF NOT EXISTS cliente (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    telefone VARCHAR(20) NOT NULL,
    cpf VARCHAR(64) NOT NULL,
    login VARCHAR(50) NOT NULL,
    senha VARCHAR(64) NOT NULL
);

-- 2. Tabela VEICULO (Com Chave Estrangeira para CLIENTE)
CREATE TABLE IF NOT EXISTS veiculo (
    id INT AUTO_INCREMENT PRIMARY KEY,
    modelo VARCHAR(100) NOT NULL,
    marca VARCHAR(50) NOT NULL,
    cliente_id INT NOT NULL,
    FOREIGN KEY (cliente_id) REFERENCES cliente(id) ON DELETE CASCADE
);

-- 3. Tabela AGENDAMENTO (Com Chave Estrangeira para VEICULO)
CREATE TABLE IF NOT EXISTS agendamento (
    id INT AUTO_INCREMENT PRIMARY KEY,
    data_agendamento DATE NOT NULL,
    servico VARCHAR(100) NOT NULL,
    veiculo_id INT NOT NULL,
    FOREIGN KEY (veiculo_id) REFERENCES veiculo(id) ON DELETE CASCADE
);

🔍 Entendendo o Código SQL Linha por Linha

  • id INT AUTO_INCREMENT PRIMARY KEY: Define o identificador único de cada linha e incrementa o número automaticamente (1, 2, 3...) a cada novo cadastro.

import hashlib
import sqlite3
from fastapi import FastAPI, Form, Request
from fastapi.responses import HTMLResponse, RedirectResponse

app = FastAPI()

# ITEM 5.4 (Peso 3): Criptografia de CPF e Senha (LGPD) em 2 linhas!
def criptografar(texto: str) -> str:
    return hashlib.sha256(texto.encode("utf-8")).hexdigest()

def get_db():
    conn = sqlite3.connect("oficina_db.sqlite")
    conn.row_factory = sqlite3.Row
    conn.execute("PRAGMA foreign_keys = ON")
    return conn

def inicializar_banco():

    conn.executescript("""

            senha TEXT NOT NULL
        );
        CREATE TABLE IF NOT EXISTS veiculo (
            id INTEGER PRIMARY KEY AUTOINCREMENT,

            id INTEGER PRIMARY KEY AUTOINCREMENT,

🔍 Entendendo o Código do Bloco 1

  • from fastapi import FastAPI, Form, Request: Importa a classe principal FastAPI, o leitor de formulários Form e o objeto Request (para ler os cookies da sessão).
  • HTMLResponse e RedirectResponse: Permitem que o FastAPI devolva páginas HTML diretamente e redirecione o usuário de uma rota para outra.
  • hashlib.sha256(texto.encode("utf-8")).hexdigest(): Transforma qualquer senha ou CPF em um código criptografado irreversível de 64 caracteres. Só essa função garante os 3 pontos do Item 5.4 (LGPD)!

🔐 PASSO 4.2: Login, Sessão com Expiração e Validação Vale 6 Pontos

Atende aos itens 3.1 (autenticar e redirecionar), 3.2 (sessão com expiração max_age=1800) e 3.3 (mensagem de erro):

@app.get("/", response_class=HTMLResponse)
def tela_login(erro: str = ""):
    msg_erro = f"<p style='color:red;'><b>{erro}</b></p>" if erro else ""
    return f"""
    <h2>Login - Oficina Mecânica</h2>
    {msg_erro}
    <form method="post" action="/login">
        Login: <input name="login" required> <br><br>
        Senha: <input type="password" name="senha" required> <br><br>
        <button type="submit">Entrar</button>
    </form>
    <p><small>Dica de teste: Login <b>ana</b> | Senha <b>123</b></small></p>
    """

@app.post("/login")
def fazer_login(login: str = Form(), senha: str = Form()):
    conn = get_db()
    user = conn.execute(
        "SELECT * FROM cliente WHERE login = ? AND senha = ?",
        (login, criptografar(senha)),
    ).fetchone()
    conn.close()

    # Item 3.3: Validação caso haja falha de autenticação
    if not user:
        return RedirectResponse("/?erro=Login+ou+senha+invalidos!", status_code=303)

    # Item 3.1 e 3.2: Redireciona e cria sessão com tempo de expiração (1800s = 30 min)
    res = RedirectResponse("/principal", status_code=303)
    res.set_cookie(key="usuario_sessao", value=user["nome"], max_age=1800)
    return res

@app.get("/logout")
def logout():
    # Item 4.2: Meio para sair do sistema
    res = RedirectResponse("/", status_code=303)
    res.delete_cookie("usuario_sessao")
    return res

🔍 Entendendo o Código do Bloco 2

  • def tela_login(erro: str = ""): Se o usuário errar a senha, o sistema redireciona para /?erro=Login+ou+senha+invalidos! e exibe a mensagem em vermelho (Item 3.3 — Peso 2).
  • (login, criptografar(senha)): Como a senha no banco está criptografada em SHA-256, criptografamos a senha digitada antes de comparar no SELECT.
  • res.set_cookie(key="usuario_sessao", value=user["nome"], max_age=1800): Cria a sessão do usuário guardando o nome dele no cookie e define a expiração para 1800 segundos (30 minutos). Essa única linha garante os 3 pontos do Item 3.2!
  • status_code=303: Faz o navegador mudar de uma requisição POST (envio de formulário) para uma requisição GET (abrir a página de destino).

@app.post("/clientes/editar")

@app.get("/veiculos", response_class=HTMLResponse)

📅 PASSO 4.6: Gerenciamento de Agendamentos Vale 5 Pontos

Atende aos itens 7.1 (listar agendamentos ordenados por data trazendo dados do veículo e do cliente) e 7.2 (atualizar a data de um agendamento):

Atenção à ordenação pedida no ORDER BY:
• Versão 1 (Dia): ORDER BY strftime('%d', a.data_agendamento) ASC
• Versão 2 (Mês): ORDER BY strftime('%m', a.data_agendamento) ASC
• Versão 3 (Ano): ORDER BY strftime('%Y', a.data_agendamento) ASC 
@app.get("/agendamentos", response_class=HTMLResponse)
def listar_agendamentos():
    conn = get_db()
    veiculos = conn.execute("SELECT id, modelo FROM veiculo").fetchall()

    agendamentos = conn.execute("""
        SELECT a.id, a.data_agendamento, a.servico,
               v.modelo AS veiculo_modelo, v.marca AS veiculo_marca,
               c.nome AS cliente_nome, c.telefone AS cliente_telefone
        FROM agendamento a
        JOIN veiculo v ON a.veiculo_id = v.id
        JOIN cliente c ON v.cliente_id = c.id
        ORDER BY a.data_agendamento ASC
    """).fetchall()
    conn.close()

    opcoes_veiculo = "".join([f"<option value='{v['id']}'>{v['modelo']}</option>" for v in veiculos])
    linhas = ""
    for a in agendamentos:
        linhas += f"""
        <tr>
            <td>{a['id']}</td>
            <td>
                <form method="post" action="/agendamentos/atualizar" style="margin:0;">
                    <input type="hidden" name="id" value="{a['id']}">
                    <input type="date" name="data_agendamento" value="{a['data_agendamento']}" required>
                    <button type="submit">Atualizar Data</button>
                </form>
            </td>
            <td>{a['servico']}</td>
            <td>{a['veiculo_modelo']} ({a['veiculo_marca']})</td>
            <td>{a['cliente_nome']} - Tel: {a['cliente_telefone']}</td>
        </tr>
        """

    return f"""
    <p><a href="/principal">Voltar para Principal</a></p>
    <h2>Gerenciamento de Agendamentos</h2>

    <h3>Novo Agendamento</h3>
    <form method="post" action="/agendamentos/criar">
        Data: <input type="date" name="data_agendamento" required>
        Serviço: <input name="servico" required>
        Veículo: <select name="veiculo_id" required>{opcoes_veiculo}</select>
        <button type="submit">Agendar</button>
    </form>
    <hr>
    <table border="1" cellpadding="5">
        <tr><th>ID</th><th>Data (Ordenada)</th><th>Serviço</th><th>Dados do Veículo</th><th>Dados do Cliente</th></tr>
        {linhas}
    </table>
    """

@app.post("/agendamentos/criar")
def criar_agendamento(data_agendamento: str = Form(), servico: str = Form(), veiculo_id: int = Form()):
    conn = get_db()
    conn.execute(
        "INSERT INTO agendamento (data_agendamento, servico, veiculo_id) VALUES (?, ?, ?)",
        (data_agendamento, servico, veiculo_id),
    )
    conn.commit()
    conn.close()
    return RedirectResponse("/agendamentos", status_code=303)

@app.post("/agendamentos/atualizar")
def atualizar_data_agendamento(id: int = Form(), data_agendamento: str = Form()):
    conn = get_db()
    conn.execute("UPDATE agendamento SET data_agendamento = ? WHERE id = ?", (data_agendamento, id))
    conn.commit()
    conn.close()
    return RedirectResponse("/agendamentos", status_code=303)

🔍 Entendendo o Código do Bloco 6

  • Duplo JOIN (JOIN veiculo e JOIN cliente): Busca os dados do agendamento, do veículo e do cliente em uma única consulta e ordena pela data com ORDER BY a.data_agendamento ASC (Item 7.1 — Peso 3).
  • Atualização rápida da data (/agendamentos/atualizar): Cada linha possui um campo <input type="date"> e o botão Atualizar Data que executa o UPDATE da data no banco (Item 7.2 — Peso 2).
